Web performance audit / homepage

sii.pl: users are fine today, slow phones are not

Real-user Core Web Vitals pass on phone and desktop. On a mid-range phone in the lab, the homepage scores 49/100 with 1.9 s of blocking time, and the hero image waits behind main-thread work. The to-do list ranks fixes by impact, starting with CSS, unused JS and tag governance.

What this means

  1. No emergency. Typical visitors are on fast desktops, and p75 field data hides the slow tail.
  2. The bottleneck is the main thread, not the server. TTFB is about 220 ms. On mobile, about 75% of LCP is render delay: the hero image has already downloaded, but the browser is too busy to paint it.
  3. Three sources of that work: a 2.5 MB (raw) stylesheet that is 97% unused, about 3 MB of raw JS including jQuery UI and Backbone, and 11 marketing vendors after consent (about 18.6 s of CPU at 4x).
  4. Interactions feel slow on mid-range phones. Opening the menu takes 536 ms at 4x CPU, and almost all of it is style and layout.
  5. No memory leak. The heap is large, but it is stable across 50 interactions.

Start with P0-1 (CSS split), P0-2 (dequeue unused scripts) and P0-3 (GTM governance). Together they move LCP, TBT and INP. See the To-do tab.

  • global.js countLines / shouldFloat: about 23 ms
  • complianz.min.js: 34 ms

P0-1Split the 2.5 MB CSS bundle, inline critical CSS, defer the restFCP, LCP, INP, memory: FCP/LCP -1.0-1.5 s, Style & Layout -50%+, heap -7 MBEffort M-L / Theme

Evidence

  • public2.1792065785088.bundle.css: 259 KiB gzip, 2,414 KiB raw, 225 KiB (97%) unused on the homepage.
  • Render-blocking, with an estimated 1,170 ms FCP saving on mobile.
  • 1.9 s of style & layout.
  • About 42k style-rule objects in the heap.

How

  1. Build per-template CSS (home, offer, blog, career) plus a small base file, and enqueue each only where it is used.
  2. Purge unused selectors with a safelist for classes that JS adds.
  3. Inline at most 14 KiB of above-the-fold CSS and load the rest without blocking.
// functions.php (theme) - per-template CSS + non-blocking load
add_action('wp_enqueue_scripts', function () {
    wp_dequeue_style('sage/public2'); // check the real handle name
    wp_enqueue_style('sii/base', asset('styles/base.css')->uri(), [], null);
    if (is_front_page()) {
        wp_enqueue_style('sii/home', asset('styles/home.css')->uri(), ['sii/base'], null);
    }
}, 20);

add_filter('style_loader_tag', function ($html, $handle) {
    if (in_array($handle, ['sii/home'], true)) {
        $html = str_replace("rel='stylesheet'", "rel='stylesheet' media='print' onload=\"this.media='all'\"", $html);
    }
    return $html;
}, 10, 2);
// postcss.config.js - purge unused selectors
module.exports = {
  plugins: [
    require('@fullhuman/postcss-purgecss')({
      content: ['./resources/views/**/*.php', './resources/scripts/**/*.js'],
      safelist: { standard: [/^slick-/, /^is-/, /^-/, /^cmplz-/], greedy: [/slick/] },
    }),
  ],
};

Verify

Lighthouse mobile x3: render-blocking insight under 300 ms, unused CSS under 50 KiB, style & layout under 900 ms. Heap StyleRule count under 10k. Menu-open INP under 250 ms at 4x CPU.

P0-2Dequeue unused WP, jQuery UI and Backbone scripts; take jQuery out of <head>TBT, LCP: TBT -400-600 ms, about 15 fewer requestsEffort S / Theme, WP

Evidence

  • The critical chain loads jQuery UI core, mouse, resizable, draggable, controlgroup, checkboxradio, button and dialog, plus underscore, backbone, api-request, wp-api and wp-emoji.
  • draggable.min.js is the longest task on the page (427 ms).
  • jquery.min.js is parser-blocking.

How

Find the plugin behind each handle with Query Monitor (Scripts panel), then:

add_action('wp_enqueue_scripts', function () {
    if (is_admin()) return;
    if (is_front_page()) {
        foreach (['jquery-ui-dialog', 'jquery-ui-draggable', 'jquery-ui-resizable', 'jquery-ui-button',
                  'jquery-ui-checkboxradio', 'jquery-ui-controlgroup', 'jquery-ui-mouse',
                  'wp-api', 'wp-api-request', 'backbone', 'underscore'] as $h) {
            wp_dequeue_script($h);
        }
        wp_dequeue_style('wc-blocks-style');
        wp_dequeue_style('wp-block-library');
    }
}, 100);

remove_action('wp_head', 'print_emoji_detection_script', 7);
remove_action('wp_print_styles', 'print_emoji_styles');

// Move jQuery to the footer (test inline jQuery calls first)
add_action('wp_default_scripts', function ($scripts) {
    if (!is_admin()) {
        $scripts->add_data('jquery', 'group', 1);
        $scripts->add_data('jquery-core', 'group', 1);
        $scripts->add_data('jquery-migrate', 'group', 1);
    }
});

Verify

Network dependency tree has no jQuery UI, Backbone or wp-api. No draggable.min.js in long tasks. Mobile TBT median drops by at least 300 ms. Manual QA: newsletter form, search, cookie banner and mega menu still work.

How

  1. Configure GA4 (G-X97HN13VEE) and the Google Ads accounts (AW-825630819, AW-969578650) as destinations of one Google tag.
  2. Fire Reddit, Facebook, LinkedIn, Bing, Leadfeeder, Apollo, OpenAI and Clarity on a page_idle event instead of Page View.
  3. Count Reddit pixel fires in GTM Preview, and remove the tag if no campaign is running.
  4. Consider server-side GTM for GA4, Ads and the CAPIs.
<script>
  function pushIdle() { (window.dataLayer = window.dataLayer || []).push({ event: 'page_idle' }); }
  addEventListener('load', () => ('requestIdleCallback' in window
    ? requestIdleCallback(pushIdle, { timeout: 4000 })
    : setTimeout(pushIdle, 3000)), { once: true });
</script>

Verify

Logged-in state

sii.pl has no logged-in mode. "Zaloguj się do MySii" leads to a separate application (my.sii.pl), which was out of scope. What differs between visitors is cookie consent, which adds 11 marketing vendors, so runs C-G use the consented state.

Caveats

CrUX is a 28-day aggregate, so a fix shows up there about 4 weeks after deployment. Each lab trace is one session, so compare medians from runs A and B. Raw traces and snapshots live in raw/ (git-ignored, ~500 MB, contains tracking IDs).
