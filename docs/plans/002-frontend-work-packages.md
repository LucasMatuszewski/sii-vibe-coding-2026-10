## Sources and fixed boundaries

Use the actual [PRD](../PRD.md), especially sections 4, 6 and 9; [ADR-001](../ADR/001-project-initialization.md) initialization/assets; [ADR-002](../ADR/002-backend-and-ai.md) sections 3.4, 3.5, 3.7 and 5; [ADR-003](../ADR/003-frontend-and-chat-ui.md); [design guidelines](../design-guidelines.md); root `AGENTS.md`; and the original `assets/homepage.png` reference. The accepted foundation is Next.js App Router, strict TypeScript and one root page. AI SDK `useChat` owns chat messages/status; selected, locally owned AI Elements Conversation/Message supply presentation. Use an application-owned native textarea composer. No full PromptInput/catalog, second chat runtime, upload in chat, model picker, reasoning display, thread history, export, editing or branching UI belongs in this MVP.

Keep case data, selected File/object URL, signed context and conversation in page memory only. No URL tokens, storage, cookies, database/session map, cross-tab channel, stream resumption or reload restoration. Backend-owned schemas under `app/src/domain/contracts/` define transport data. The frontend validates public response envelopes; it does not possess the signing secret or claim to cryptographically verify JWT signatures. Server responses remain the authority for outcomes, policy references and canonical messages.

Only these real endpoints are used: `POST /api/cases/analyze`, `POST /api/cases/decide`, `POST /api/chat`. The first decision is complete and validated before display; it seeds the first assistant message once without another generation. Follow-up narrative streams live. A new signed context, canonical assistant message and optional revised decision become authoritative together only when a valid final `data-commit` and successful, non-error finish both belong to the active attempt. Partial text, an early commit event or apparent decision words in Markdown never change the committed badge.
